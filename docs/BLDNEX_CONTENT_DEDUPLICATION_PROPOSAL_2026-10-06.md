# 홈·상세 페이지 콘텐츠 중복 정리 제안

상태: **적용 완료 (`feat/page-differentiation` 브랜치)**  
작성일: 2026-10-06  
반영일: 2026-10-07  

## 검토 목적

홈은 빠른 이해와 다음 페이지로의 이동을 돕고, 각 상세 페이지는 근거와 실행 정보를 확장하는 역할을 갖는다. 현재 구조는 이 원칙을 대체로 따르지만, Works·자체 제품 경험·프로세스 세 구역은 같은 정보가 화면과 문장 단위로 반복된다.

## 제안

### 1. 홈 Selected Works를 실제 선별 사례로 축소

- 현재: 홈과 `/works` 모두 `PreviewLog`, `Shuffo`, `bldnex.com` 카드 전체를 동일하게 표시한다.
- 제안: 홈에는 `PreviewLog`와 `Shuffo` 두 사례만 보이고, `bldnex.com`은 히어로의 실측 스탬프에서 연결하는 기술 증거 역할을 유지한다.
- 기대 효과: “SELECTED WORKS”라는 표기와 실제 구성이 일치하고, `/works`의 전체 목록 역할이 분명해진다.

### 2. 자체 제품 운영 경험은 About에 집중

- 현재: 홈 Studio와 About Hero·Our Own Products가 PreviewLog·Shuffo를 직접 운영하며 우선순위를 판단한다는 메시지를 반복한다.
- 제안: 홈은 한 문장의 근거와 About 링크만 둔다. 제품별 운영 경험과 ‘지금 필요한 것 / 나중에 해도 되는 것’의 판단 근거는 About에 둔다.
- 기대 효과: 홈의 읽는 흐름이 가벼워지고, About으로 이동할 이유가 선명해진다.

### 3. 프로세스는 홈에서는 개요, About에서는 협업 운영 기준으로 분리

- 현재: 홈 Process와 About Working Together가 동일한 4단계 컴포넌트와 산출물 예시를 사용한다.
- 제안: 홈은 `Understand → Shape → Build → Ship`의 단계명과 한 줄 설명만 보여 준다. About은 다음 실제 협업 기준을 안내한다.
  - 시작 기준: 목표·사용자·자료·의사결정 방식 정리
  - 검토: 주요 화면과 동작을 보며 결정 지점 확인
  - 변경 관리: 범위·일정·우선순위 영향 공유 후 선택
  - 인수: 배포 결과·운영 정보·후속 과제 정리
- 기대 효과: 홈은 전환을 위한 이해를, About은 함께 일할 때의 신뢰를 담당하게 된다.

## 유지할 반복

- 홈의 FAQ 3개와 Contact의 전체 FAQ 7개는 ‘핵심 질문 미리보기 → 전체 안내’ 구조이므로 유지한다.
- 서비스 카드와 Services 상세는 ‘요약 → 범위·산출물·준비 정보’ 역할이 달라 유지한다. 홈 카드의 설명이 길어질 때만 축약을 검토한다.
- 페이지별 문의 CTA와 푸터의 브랜드 메시지는 일관된 전환 장치이므로 유지한다.
- Services 하단의 진행 방식 링크는 About으로의 이동을 돕는 보조 안내이므로 우선순위가 낮다.
